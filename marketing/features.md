<!-- feature-intro -->
Bugsnag connects Craft’s server and browser errors to the error-monitoring workflow your team already uses. Capture useful context automatically, then add the breadcrumbs and metadata that make a report actionable.
<!-- feature-intro-end -->

<!-- feature-section -->
## Errors with context

An error report that only says something broke is barely a head start. Send Craft exceptions and selected log messages to Bugsnag with the release, request and user context needed to understand where the problem happened, while filters keep noisy or sensitive values out of the payload.

<!-- feature-section-end -->

<!-- feature-grid -->
- :icon[bug] **Exception reporting** Send Craft and PHP failures to the correct Bugsnag project automatically.
- :icon[list-details] **Yii log target** Forward selected warning and error categories with configurable exclusions.
- :icon[filter] **Payload filters** Remove passwords and other nominated values before reports leave the site.
- :icon[settings] **Environment controls** Set release stages, application versions, user data, and ignored traffic per project.
<!-- feature-grid-end -->

<!-- feature-section -->
## Follow the trail

See the path that led to a failure, not only the final exception. Browser reporting catches front-end JavaScript errors, breadcrumbs record important events from PHP or Twig, and optional Commerce context adds useful order and transaction identifiers without including payment or address details.
<!-- feature-section-end -->
